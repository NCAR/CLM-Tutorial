Run_tower: NEON#

Exercise: use the run_tower script to run a single point case at a NEON site

Create a case at the Abby Road site called ABBY.transient using the run_tower script in tools/site_and_regional that uses the latest NEON input data (as of writing this tutorial, v4).

Note: You will need to activate the ctsm_pylib conda environment to use the run_tower script. After creating your case you can check the status of the run after submitting.

Please ensure that you have completed all steps in the Download CTSM Tutorial, especially setting up your ctsm_pylib conda environment, before starting this exercise!

Background#

NEON sites include the following:

 ABBY,BARR,BART,BLAN,BONA,CLBJ,CPER,DCFS,
 DEJU,DELA,DSNY,GRSM,GUAN,HARV,HEAL,JERC,
 JORN,KONA,KONZ,LAJA,LENO,MLBS,MOAB,NIWO,
 NOGP,OAES,ONAQ,ORNL,OSBS,PUUM,RMNP,SCBI,
 SERC,SJER,SOAP,SRER,STEI,STER,TALL,TEAK,
 TOOL,TREE,UKFS,UNDE,WOOD,WREF,YELL

You can find out more information about all of the terrestrial sites at the NEON science website.

Assumptions#

Here are some assumptions we’ve built into NEON simulations that use the run_tower script:

  • Surface datasets: have a single plant functional type (PFT) that we consider ‘dominant’ for each NEON tower.

  • Surface datasets: have modified soil properties that are intended to match observations from the NEON MegaPit sampling.

  • DATM: are gap filled from NEON and mostly cover 2018-2024, although individual sites may have custom data ranges.

  • Compset: You’ll be running a BGC case, but if you run an SP case the LAIs have not been adjusted with site conditions.

  • Parameter file: are default for the physics version of CLM being used. They have not been calibrated to site-level observations.

  • Initial conditions: We provide initial conditions that were generated using an AD and postAD spinup for each site. Therefore, the default run-type is called ‘transient’, which means you’ll get time-varying CO2, nitrogen deposition, and aerosol deposition (from CMIP6 era forcings). Our aim is to generate new initial condition files that are consistent with the major release version of CLM (i.e., CLM6). You may need to spinup the model if you’re using a different code base, parameter file, or surface dataset.

Get started#

Let’s use run_tower at a NEON site.

What run_tower does

A single run_tower command handles the whole CTSM workflow (create, setup, build, and submit). For a NEON site it does four things, in order:

  1. Builds a base case (e.g., ~/cases/ABBY). This compiles CTSM once and takes a few minutes.

  2. Clones the base case into the case you’ll actually run (~/cases/ABBY.transient). The clone reuses the compiled model, so adding more sites to the run_tower command (e.g., --neon-sites ABBY BART) is fast.

  3. Downloads the site data: the atmospheric forcing (DATM) and initial conditions, from NEON’s servers. This step prints a lot of output to the screen. If the NEON servers are slow or down, it can fail. You can re-run the same command with --rerun.

  4. Submits the ABBY.transient case to the queue.

Once it has been submitted, check on your job with:

qstat -u $USER
Click here for the solution

activate ctsm_pylib:

conda activate ctsm_pylib

move into the tools/site_and_regional directory and ask for help!

cd /glade/u/home/$USER/code/my_clm_code/tools/site_and_regional
./run_tower --help

Make sure that ~/cases/ already exists (mkdir -p /glade/u/home/$USER/cases). run_tower will error if your specified --output-root doesn’t exist yet.

Create a new case ABBY.transient with the command:

./run_tower --neon-sites ABBY --output-root ~/cases/. --xmlchange PROJECT=UCGD0011

During this time run_tower will complete steps 1-4 listed above. This takes some time, so be patient. But you can track progress in your case directories.

Check that the case is setup:

cd /glade/u/home/$USER/cases/ABBY.transient
cat CaseStatus

Check the job status:

qstat -u $USER

When the run is completed, look into the archive directory for: ABBY.transient.

Check that your archive directory contains outputs (put in ~/cases/archive because we specified --output-root ~/cases/):

cd ~/cases/archive/ABBY.transient
ls
